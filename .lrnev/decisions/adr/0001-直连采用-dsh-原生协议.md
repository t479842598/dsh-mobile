# ADR 0001 — 直连模式采用 DSH 原生协议（RPC POST + 双下行 WS）

- 状态：accepted
- 日期：2026-08-23
- 范围：global

## 背景

dsh-mobile 此前仅支持经 `dsh-plugin-mobile-gateway` / `dsh-plugin-mobile-bridge` 的私有移动网关协议（`/ws/mobile`，配对码/token）。用户要求不动网页端（DeepSeek Harness 及其插件），让 App 直接以"浏览器同等方式"连接网页端，含远程域名。

调研结论（源码级）：

- `dsh-passwords`（≥2.5.1）：`GET /gateway/login` 下发 CSRF（Cookie `dsh_csrf`），`POST /gateway/login` 表单提交换取 `dsh_gateway_token` JWT Cookie（12h）；HTTP 与 WS 升级均凭此 Cookie 鉴权。
- DSH 原生协议（`@deepseek-ai/dsh-host-apiproxy` / `dsh-client-connection`，实测包版本 0.1.1-rc.2）：RPC 为 `POST /api/<method>`（四象限信封 client-request/server-response）；事件为两个**仅下行**的 WebSocket `/api/events.mux`、`/api/events.host`（GET 返回 426 Upgrade Required，SSE 在该版本不可用；客户端发消息会被 1008 关闭）；应答 answerable 帧（审批/提问）用 `POST /api/respond`。
- 信任围栏 `isTrustedApiRequest` 仅校验 Host 头 ∈ trustedHosts、可选 Origin 同源——原生客户端天然满足。

## 决策

新增独立 Direct 连接栈，直接实现上述原生协议；不扩展移动网关协议，不改网页端。状态层通过"原生→GatewayFrame"翻译器复用既有 AppStore 管线与全部视图。

## 备选方案

- 扩展 `/ws/mobile` 网关协议承载原生能力 → 需要改插件（违反"不动网页端"约束），放弃。
- App 内嵌 WebView 加载网页端 → 体验与原生差距大、且 iOS 上 WebView 对该前端兼容成本高，放弃。
- SSE 承载事件流 → 服务端该版本明确返回 426，不可行。

## 后果

- App 与网页端共享同一协议面，网页端升级时只需跟随 apiproxy 契约（宽松解码兜底未知字段）。
- 直连栈需自行处理 Cookie 鉴权、双流生命周期与重连；复杂度集中在 Core/Direct 内部，UI 与状态层几乎零改动。
